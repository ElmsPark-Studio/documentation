EP Locations turns each branch of a multi-location business into its own PageMotor page (`/locations/wexford-quay-street/`), emits a Schema.org `LocalBusiness` JSON-LD node per branch back-referencing a single brand-level `Organization`, and ships with a built-in MapLibre store finder. Each location can be a different `LocalBusiness` subtype — one branch a `Restaurant`, another a `FastFoodRestaurant`, the corporate office a bare `LocalBusiness`. Everything settings-driven and overridable per branch.

For single-location businesses, install [EP Local Business](/plugins/ep-local-business/) instead. EP Local Business defers automatically when EP Locations is installed and active.

Published by [ElmsPark Studio](https://elmspark.com).

## What EP Locations does

- **Each location is its own URL.** Registers the `location` content type with PageMotor — admin CRUD is auto-generated by the core, no plugin code required.
- **Per-location subtypes.** Mixed chains supported: one `Restaurant`, another `FastFoodRestaurant`, one `LocalBusiness` for the corporate office. 30 curated subtypes plus an "Other / Custom…" override.
- **Pattern B Schema.org graph.** Single `Organization` parent at `<site_url>#organization`, each branch's `LocalBusiness` node at `<location_url>#localbusiness` with `parentOrganization` back-reference. Mirrors what Yext (powering Wendy's, T-Mobile, Best Buy) emits in production. Doesn't enumerate `subOrganization` arrays — wasteful and Google infers the inverse anyway.
- **Built-in store finder shortcode** (`[locations_finder]`) with MapLibre GL JS + MapTiler Cloud tiles (EU-based, GDPR-friendly, 100k loads/month free, no credit card).
- **Two search modes.** Postcode/address input (server-side geocoded via OSM Nominatim, biased to your default country) or HTML5 geolocation (click only — never auto-prompted).
- **Filters.** Distance radius and per-location subtype (the subtype filter only renders when the chain has more than one).
- **List-first mobile UX** with a peek-map at the top — no fragile bottom-sheet pattern.
- **Per-location detail shortcode** (`[location_details]`) for themes that don't ship a custom `location` template.
- **OG business contact-data tags** on every location page (`og:type=business.business`, `og:business:contact_data:*`).
- **Coexistence** with EP SEO and EP Local Business — clean handshake hooks, no double-emission.
- **Per-location overrides** for price range, payment methods, currencies, profile URLs, VAT/tax IDs.
- **Opening hours grid** with multi-interval days and automatic overnight splitting (22:00–02:00 emits as Mon 22:00–23:59 + Tue 00:00–02:00 per Schema.org's spec).

## What EP Locations doesn't do

- **"Open now" filter on the finder** — the helper exists but the finder UI doesn't expose it in v1.0 because per-location timezones aren't a field yet. v1.1 candidate.
- **Holiday or special opening hours overrides.** Same gap as EP Local Business.
- **Bulk CSV/JSON import.** Locations created one at a time via PM admin. v1.1+ candidate.
- **Map clustering.** Chains over ~50 locations on one map will get dense — MapLibre supports clustering but it's not wired in v1.0.
- **`hasOfferCatalog` (structured services with prices), `aggregateRating`, review CRUD.**

## Requirements

- **PageMotor 0.8.3 or later.** Required for the framework CSRF system used by the AJAX endpoints.
- **MapTiler Cloud API key** for the store finder map. Sign up at [maptiler.com/cloud](https://www.maptiler.com/cloud/) — free tier covers 100k map loads per month with no credit card. Without a key the finder still works, just degrades to list-only with no map.
- **EP SEO 1.4 or later** — optional. Needed for the Organisation handshake in merged mode (so EP SEO yields its Organisation branch when EP Locations owns it).

## Installation

1. Download `ep-locations.zip` from your EP Suite distribution.
2. Upload via **Plugins → Manage Plugins**. Activate.
3. Open the plugin's settings page and tick **Enable LocalBusiness schema for all locations** in the Master Switch section.
4. Fill in the Parent Organisation fields (or rely on EP SEO 1.4 to provide them).
5. Get a free MapTiler API key from [maptiler.com/cloud](https://www.maptiler.com/cloud/) and paste it into the Store Finder section.
6. Set sensible per-location defaults: country, default subtype, default payment methods. These pre-fill new locations and are overridable per branch.
7. Create your first location: **Admin → Content → Add → Location**. Fill in the Location Details panel. Save.
8. Drop `[locations_finder]` into a page (typically `/locations/`). Drop `[location_details]` into your location template, or into each location's content area, to render the detail block.

## Settings

The settings page has six sections.

### Master Switch
- **Enable LocalBusiness schema for all locations.** Master gate. Required.

### Parent Organisation
Brand-level identity. Used as the parent `Organization` node when EP SEO is not present, and as a fallback layer when EP SEO doesn't have a value.

- **Organisation Name, Description, Logo URL, Profile URLs (one per line)**

### Per-Location Defaults
Defaults applied to every location unless overridden.

- **Default LocalBusiness Subtype.** Used when a location hasn't picked its own. Override per branch for chains with mixed types.
- **Default Country (ISO 3166-1).** Pre-fills new locations and biases postcode geocoding.
- **Default Price Range, Payment Methods, Currencies.**

### Store Finder
- **MapTiler API Key.** Required for the map. Without one, the finder runs in list-only mode.
- **Default Radius (km).** What "Within X km" defaults to in the finder filter.
- **Initial Map Zoom + Default Centre (lat,lng).** Where the map opens before the user searches. Default centres on Ireland; pick something appropriate for your region.

### Integration
- **Coexistence Mode.** Merged (recommended for typical chains — single Organisation parent that all branches reference) or Additive (separate Organisation stays distinct, for franchises with a separate parent legal entity).

### Tools
- **Show location inventory** — lists every live location with name, type, address, coordinates, and a view link.
- **Open Schema.org validator** — deep-link to validator.schema.org with your site origin pre-filled.

## Per-location fields

Each location has its own fields under **Location Details** in the content editor:

- **Display Name** (overrides the page title in schema/OG)
- **LocalBusiness Subtype** (per-branch override of the sitewide default)
- **Description, Address, Geo coordinates** (with one-click OSM Nominatim geocode)
- **Telephone, Email, Logo, Photo URLs**
- **Opening Hours grid** (full weekly schedule with multi-interval days, copy-to-all, automatic overnight splitting)
- **Per-location overrides:** price range, payment methods, currencies
- **Branch-level Profile URLs** (sameAs)
- **VAT ID, Tax ID**

## Shortcodes

### `[locations_finder]`

Renders the store finder anywhere on your site — typically on a `/locations/` parent page.

Outputs the search form (postcode/address input + "Use my location" button), MapLibre map (or list-only fallback if no API key), filters (distance radius + per-location subtype), live status line, and the results list. The list and map are bound — clicking a list item highlights its marker; clicking a marker opens a popup with name, address, and a link.

```
[locations_finder]
```

No attributes in v1.0 — settings come from the plugin's sitewide configuration.

### `[location_details]`

Renders the per-location detail block (name, description, address, contact, opening hours table, map link).

```
[location_details]            (defaults to the current location page)
[location_details id="42"]    (renders a specific location elsewhere)
```

Useful for themes that don't ship a custom `location` template — drop the shortcode into your default Page template's content area and every location page renders the detail block automatically.

## Coexistence with EP SEO and EP Local Business

EP Locations sits at the top of the LocalBusiness coexistence chain.

- **EP Local Business** defers entirely whenever EP Locations is installed and active. There is no double-emission. The defer is one-way: EP Local Business reads EP Locations; no reciprocal handshake required.
- **EP SEO** yields its `Organization` branch when EP Locations is in **merged** mode (the default). The combined parent Organisation carries EP SEO's name/url/description plus EP Locations' organisation-level fields, all under `#organization`.
- **EP SEO additive mode**: EP SEO emits `Organization` as normal at `#organization`. EP Locations adds branches with `parentOrganization` back-references. This suits chains with a separate parent legal entity that should remain schema-distinct.

### Coexistence matrix

| Setup | Behaviour |
|-------|-----------|
| EP Locations alone | Owns `Organization` + per-location `LocalBusiness` nodes. |
| EP Locations + EP SEO (merged) | EP SEO yields Organisation. EP Locations emits the parent + branches. |
| EP Locations + EP SEO (additive) | EP SEO emits Organisation unchanged. EP Locations adds per-location LocalBusiness nodes with `parentOrganization` back-references. |
| EP Locations + EP Local Business | EP Local Business defers entirely. EP Locations owns all LocalBusiness emission. |
| EP Locations + EP SEO + EP Local Business | EP Local Business defers. EP SEO yields per its merged/additive setting against EP Locations. |

## Privacy and EP GDPR

EP Locations is built for UK and EU sites. The store finder uses three things that touch external services or visitor data, and all three are gated cleanly when [EP GDPR](/plugins/ep-gdpr/) is installed and active.

### Third-party services used

| Service | When | What flows | Where |
|---------|------|------------|-------|
| MapTiler Cloud | Every map render in the public finder | Visitor IP, viewport bounds | EU (MapTiler is Czech-headquartered, EU data residency) |
| OpenStreetMap Nominatim | Each postcode/address search the visitor runs | Visitor IP, the typed query | OSM Foundation (UK, with mirrors) |
| HTML5 geolocation | Only when the visitor clicks "Use my location" | Approximate coordinates, browser-mediated | Stays on the device until the visitor clicks Search; then sent to your server with the rest of the request |

Admin-side geocoding (the "Look up coordinates from address" button on each location's editor) is admin-only and exempt from visitor consent gating — admins are logged-in users acting on the site's own data.

### When EP GDPR is active

If [EP GDPR](/plugins/ep-gdpr/) is installed and active alongside EP Locations, the entire `[locations_finder]` shortcode is gated behind the **analytics** cookie category:

- **Without analytics consent** — the finder shows a friendly explainer ("Store finder requires analytics cookie consent. The map and postcode search are third-party services that see your IP address.") and an **Open cookie settings** button. Clicking the button clears the EP GDPR consent cookie and reloads the page, which re-shows EP GDPR's banner so the visitor can choose again.
- **With analytics consent granted** — the finder loads normally: map tiles fetch from MapTiler, search hits Nominatim, geolocation is offered.
- **If consent is granted while the visitor is on the page** (without leaving) — the finder listens for EP GDPR's `ep_gdpr_consent_changed` event and re-boots itself when consent flips on. No reload needed.

The gate is enforced in two places:
1. **Client-side** — the finder JS checks the `ep_gdpr_consent` cookie before initialising MapLibre or rendering the search form.
2. **Server-side** — the public AJAX endpoint (`finder()` action) refuses with `reason: gdpr_consent_required` if the cookie is missing or has `analytics: false`. This is defence in depth — a direct POST to the AJAX endpoint can't bypass the JS gate.

### When EP GDPR is not installed

EP Locations behaves exactly as it always did — the finder loads on page load, the map renders, postcode search works. The gate code is dormant. No behaviour change for sites that aren't running EP GDPR.

### Recommended cookie category

Map your `ep_gdpr_consent` "analytics" category to the third-party services EP Locations uses:

> "We use MapTiler Cloud (EU-based mapping service) and OpenStreetMap (community-run geocoding) on our store finder. These services see your IP address while you're using the map or searching for a location. Accept analytics cookies to enable the store finder."

Adjust phrasing for your site's voice. EP GDPR's cookie banner text is editable in its settings.

## Action / boundary methods (for AI agents and CLI scripts)

EP Locations follows the PM 0.8.3b action/boundary pattern. Five actions are exposed as public methods callable directly without simulating a POST:

| Action | Returns | Auth |
|--------|---------|------|
| `geocode($query, $country_hint)` | `['success', 'lat', 'lng', 'display_name']` or failure | Admin only via boundary |
| `finder($filters)` | `['success', 'locations', 'center', 'count']` | **Public** (anonymous-safe) |
| `inventory()` | `['success', 'locations']` | Admin only via boundary |
| `preview_node($location_id)` | `['success', 'json_ld']` | Admin only via boundary |
| `validate_hours($hours)` | `['success', 'errors', 'schema']` | Admin only via boundary |

Each has a paired `<name>_post()` boundary that reads `$_POST`, performs the auth check (where applicable), and echoes JSON. The framework CSRF system in PM 0.8.3b handles request validation for authenticated POSTs automatically — the public finder is anonymous-safe by design.

## Troubleshooting

### "I created a location but no schema appears in the page source"

Three things to check:

1. **Master switch** is on (Settings → Master Switch).
2. The location's status is **live**, not draft.
3. The address has at least street + locality + country populated. Without those, the location has nothing to emit and the OG tags won't fire either.

### "The store finder shows a grey box where the map should be"

Either the **MapTiler API key** is missing/wrong, or the MapLibre script blocked. Open the browser console — if you see "Map library failed to load" or the key is rejected, fix the key in Settings → Store Finder. Without a key, the finder shows a list-only fallback with a friendly "Map disabled" message.

### "Geolocation button asks for permission every time"

That's how the browser works — first time per origin, the user grants/denies permission. EP Locations never auto-prompts geolocation; it only fires on click, which is the consent-respecting pattern. If a user grants permission once, the browser remembers; if they deny, they can re-enable in site permissions.

### "Postcode search returns 'No match found' for valid addresses"

Nominatim's coverage is excellent for high-density urban addresses but patchy for rural or recently built ones. Two fixes:

1. Set the **Default Country** in plugin settings — the geocoder biases results to that country, which dramatically improves accuracy for ambiguous queries.
2. If a specific postcode still fails, try the town + region instead.

### "Two locations have the same coordinates and only one marker shows"

MapLibre overlays markers at identical coordinates. Either nudge the geo of one (Nominatim sometimes returns a country/county centroid for vague addresses), or wait for the v1.1 clustering feature.

### "I want one chain to look like Organization, not LocalBusiness, in the parent node"

That's the default — the parent at `#organization` is always typed `Organization`, never `LocalBusiness`. Only the per-location nodes carry the `LocalBusiness` subtype. Check the Schema.org validator output to confirm.

### "EP SEO is still emitting Organisation and so am I"

You're in **additive mode**, which is the intended behaviour. Both nodes appear in the @graph. If you wanted a single combined node, switch to **merged mode** in Settings → Integration.

### "I installed EP Local Business and now schema is missing on my single-business homepage"

EP Local Business defers entirely when EP Locations is installed and active. If you're a single-location business, **uninstall or deactivate EP Locations** — EP Local Business is the right plugin for that case.

### "The store finder loads but shows zero results"

Either no live locations exist (Admin → Content → Locations) or your filters are excluding them all. Reset the radius filter to "Any distance" and untick all subtype filters. If the finder still shows zero, run the **Show location inventory** tool in Settings → Tools to verify the locations exist in the database.

### "I want each branch's hours to respect a local timezone"

Not in v1.0. The hours grid stores wall-clock times; the schema emits them as-is. The `is_open_now()` helper accepts a timezone argument but no per-location timezone field exists yet. Planned for v1.1, when the "Open now" finder filter ships.
